Скорость индексации

Как индексер добирается до головы чейна и сколько это стоит. Лента ниже — жизненный цикл реиндекса: кликните стадию, откроется карточка дежурного (что происходит, едет ли, что может смутить, застряли ли, ETA). Секции под лентой — цена вопроса для планирования: юнит-косты блоков, взаимовлияние индексов, датасорсы. Все числа измерены на mainnet в июне–июле 2026, но модель и ставки — свойства механики индексера и переносятся на любую пару «L1 + роллап» (как пересчитывать — секция «перенос»); сырьё и окна замеров — в конце.

жизненный циклвсем

Пять стадий от пустой базы до головы

Модель стадий одна для любой пары «L1 + роллап» — от сети к сети меняются только длительности (пересчёт — в секции «перенос»). Ширина сегмента ≈ доля общего времени; подстановки — mainnet 06-2026, полный прогон — 3 сут 11 ч. Узкие стадии 0–1 раздвинуты для читаемости, честные доли — на тонкой шкале под лентой.

проверкаагенту

curl -s https://<host>/v1/graphql -H 'content-type: application/json' \
  -d '{"query":"{ dipdup_index { name status level updated_at } dipdup_head { name level timestamp } }"}'

Остаток L2 в оценку не входит — L2 финиширует раньше при любом реалистичном раскладе.

перенослюдям

Как перенести на другую пару L1 + роллап?

Стадии, их сигнатуры и юнит-косты — свойства механики индексера, они переносимы. Пересчитываются только длительности: по длине L1-диапазона и насыщенности L2-блоков.

У индексера шесть конфигов-оверлеев (mainnet, ghostnet, quebecnet, rainbownet, shadownet, tezosx-shadownet) — разные пары «L1-сеть + роллап», механика везде одна: один цикл событий, L1-скан уровень за уровнем, Subsquid пропускает пустые блоки. Поэтому лента стадий и пороги проверки применимы к любой паре, а вот доли сегментов и «3.5 суток» — подстановка mainnet.

стадиячем определяется длительностьпересчёт · проверка на живых прогонах
Тишинадлина сканируемого L1-диапазона (от подключения роллапа до головы)уровни L1 / 425 lvl/s mainnet: ~8.1M → ~5.3 ч ✓ · tezosx-shadownet: ~0.78M → прогноз ~30 мин, факт ~20 мин ✓
Разлётнасыщенность L2: пустые блоки бесплатнына слабонасыщенном роллапе (тестнеты) весь L2 добегает уже в Разлёте tezosx-shadownet: весь L2 (0.8M) и весь пустой L1 — за ~2 мин ✓
Толпа + Спринтдлина L1-диапазона — полюс всегда L1уровни L1 / ~1.5k lvl/min mainnet: ~6.8M → ~3.2 сут ✓ · tezosx-shadownet: стадий не возникло — на пустом L1 всё добегает в Разлёте ✓
Реалтаймтемп блоков конкретной пары чейновскорость = блоктаймы, не индексер mainnet: 0.86 / 0.165 lvl/s

Условие всей модели — живой Subsquid-архив на L2. «Пустые блоки бесплатны» — свойство архива, а не сети. Проверено на одной и той же паре (tezosx-shadownet, июнь 2026): с подключённым архивом полный реиндекс занял ~23 минуты; двумя днями раньше, без архива в конфиге, L2-бэкфилл шёл напрямую через EVM-ноду на ~1k lvl/min со штормами 503 — за 11.5 часов прошёл две трети диапазона, два из четырёх L2-индексов вообще не начали, а уже догнавшие голову L1-индексы простояли замороженными 10 часов: весь цикл занят L2. Разница на два порядка — от наличия одного датасорса. Первая проверка при переносе: архив для этого роллапа существует и его высота растёт.

Что перемерять при переносе: плотность блоков с событиями на конкретном роллапе (у mainnet она падает 82% → 16% с возрастом чейна — у другого роллапа кривая своя). Плотность L1-эпох тоже своя: эталон полюса ~470–2000 lvl/min намерен на бридж-активности mainnet — на пустом тестнетовом L1 полюс поедет быстрее.

Оговорка про хост, самая дорогая: тот же код и та же БД на другой Swarm-ноде работали в 3–4.5 раза медленнее — 3.5 суток mainnet превращаются в полторы-две недели. Прежде чем планировать реиндекс на любой сети, убедись, что нода не перегружена соседями. И длительности растут вместе с чейном: подстановки в таблице — июль 2026.

юнит-костылюдям

Сколько стоят 1000 блоков — пустых и активных?

На L2 пустые блоки бесплатны, платим только за блоки с событиями. На L1 наоборот: платим за каждый уровень, есть там бридж-операции или нет.

L2 · 1000 пустых блоков

~0.3 cSubsquid отдаёт только совпавшие блоки — пустые пролетают пачками по 100–200 тыс.

L2 · 1000 блоков с трансферами

~10–15 c≈11 мс на блок с ERC-20 Transfer (самый нагруженный тип события)

L1 · 1000 блоков, пустая эпоха

~4 cранний диапазон, бридж-операций почти нет

L1 · 1000 блоков, активная эпоха

30 c – 2 мин30 с — когда цикл свободен; 2 мин — в толпе с другими индексами

Как это влияет на итог. У L2 уровней в шесть раз больше (44M против 7M), но насыщенность решает: доля блоков с трансферами падает со временем — 82% в эпоху 12M → 45% на 30M → 16% на 46M (замер по архиву), а бридж-события и вовсе в ~0.07% блоков. Поэтому индекс редких событий пролетает все 44M уровней за полчаса, индекс трансферов возится сутки-трое, а L1 со своими «всего» 7M уровней — всегда длинный полюс: его цена почти не зависит от того, использовался бридж или нет.

контеншнлюдям

Насколько индексы мешают друг другу?

Сильно: в толпе отдельный индекс работает в 4–16 раз медленнее, чем в одиночку. Суммарная скорость при этом не падает — цикл просто делится иначе.

Все девять индексов делят один Python event loop и одно соединение с БД — это и есть потолок (датасорсы быстрее в ~1000 раз, см. секцию ниже). Измерено на одном и том же индексе в одном прогоне: L1-полюс — 470 lvl/min в толпе против 2000+ после финиша соседей (×4.3); индекс трансферов — ×16. В худшем случае один прожорливый индекс съедал 48% всего цикла, остальные голодали.

Два практических следствия. Скорость индекса в середине катчапа — это его доля в делёжке, а не его способность: экстраполировать по ней «не успеет за месяц» нельзя — хвост добегает Спринтом. И наоборот: «залипший» индекс при живых соседях — почти всегда голодание, а не баг (на карточке «Толпа» это пункт «что может смутить»).

датасорсылюдям

Что дают датасорсы и где разница L1 / L2?

Ни один датасорс не лимитирует: у самого нагруженного запас ×1000 над тем, что индексер способен переварить. Разница L1/L2 — в модели оплаты: L2 платит за события, L1 — за уровни.

датасорсрольчто о нём знать
Subsquid-архив L2весь L2-катчапотдаёт ~1000× быстрее, чем индексер потребляет; пустые уровни пропускает — отсюда «бесплатные» пустые блоки L2. Свой архив с нуля строится за ~26 ч
EVM-нода L2последняя миля + realtimeв катчапе не участвует вовсе (включается за 128 уровней до головы); на скорость бэкфилла не влияет
TzKT L1весь L1 + скан rollup-сообщенийпроход линейный, уровень за уровнем — поэтому L1 и есть длинный полюс; сам API не лимит
Rollup-нода L1outbox-пруфыфоновая работа, на темп катчапа не влияет; её 500-ки в логах — шум

Почему упираемся не в них: вся обработка — один event loop и одно DB-соединение, коммит за коммитом. Единственный измеренный способ существенно ускориться без правки кода — хост получше (×3–4.5); «докупить датасорс» не даёт ничего.
