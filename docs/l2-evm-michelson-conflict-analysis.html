EVM & Michelson
collide in L2

×4

The indexer was designed for one L2 runtime — EVM. Tezos X added a second, Michelson, and its XTZ deposits were written into the EVM-shaped tables "by analogy". The result is not one problem but four independent axes of collision. Row class is convention, not data — on 2026-06-11 that already cost 12 wrong matches in production. This is a fresh pass over every L2 model, the conflict map, and the re-derived fix.

Michelson row— synthetic Tezlink op: base58 "o…" hash, tz-addresses, native mutez (6-dec), Tezlink level EVM row— the table's native shape: hex hashes, H160, wei (18-dec), EVM block number
01 · reframe

It isn't one "kind" — it's four axes

the word "kind" was doing triple duty · each axis is independent and owns a different failure

The trap is treating EVM-vs-Michelson as a single switch. A deposit to a tz1 user's EVM alias is runtime=evm (hex hash, wei, EVM matcher) yet beneficiary=tz. One column cannot carry both. Untangled, the surface is four orthogonal questions:

A · Runtime

how was the row produced?

evm vs michelson. Today inferred by convention: transaction_hash.startswith('o') (×2) and inbox_…__isnull.

Owns → the matcher bug.

B · Beneficiary

who owns the funds?

evm-eoa / tz-native / evm-alias-of-tz. The alias machinery (Initialized-event registry) is not built yet.

Owns → address format + alias/UI.

C · Asset / units

what asset, at what scale?

EVM is native wei (18-dec); Michelson is native mutez (6-dec). Today forced to one wei column via ×10¹².

Owns → decimals + amount string-magic.

D · Level space

which chain's block number?

EVM block (~388k) vs Tezlink level (~562k) from a different chain — incomparable, yet sorted together.

Owns → the ordering hazard.

05 · the fix

Make each axis data, not convention

re-derived per axis · one schema pass · backfill = full reindex while data is test-net only

RESOLUTION · A → D + cross-cutting
A

Explicit l2_kind on l2_deposit, l2_withdrawal & bridge_operationruntime

Enum(evm | michelson), set by the handler. All 3 convention discriminators (startswith('o'), isnull) become one honest filter + a disjoint-pools test. On bridge_operation too, so UI / Hasura / Kuma filter runtime without a join. Withdrawal column is constant evm today — kept for symmetry.

B

l2_account → FK to a normalized L2Account tablebeneficiary

The row stores both the on-chain address (matcher keys on it) and the resolved native origin, under distinct names, plus kind ∈ {EVM, TZ, EVM_ALIAS}. Origin = native_tz for an alias, else the address itself — a read concern, not a write. One-row retroactive enrichment via JOIN; the table doubles as the decided alias registry. Sequenced: store the tz1 string now for the deposit fix; introduce the FK in block 2 with the alias indexing that feeds it.

C

Split XTZ into two token rows; derive scale from decimalsasset/units

A wei/18-dec row (EVM) and a mutez/6-dec row (Tezlink); store native units, consumers normalize via token.decimals — the path FA tokens already use. Cost, accepted: EtherlinkToken.ticket OneToOne→ForeignKey (one L1 ticket, two L2 rows), exempt XTZ from the on_deposit.py:27 one-ticket-one-token guard, and SUM across both rows for "total XTZ". The op-hash ×10¹² stays — the kernel hashes wei regardless.

D

Default-order by timestamp, not levellevel space

Meta.ordering = ('-timestamp', '-transaction_index'). Block wall-clock is comparable across both chains; level stays as native per-row metadata, only ever compared within one l2_kind. Removes the only real hazard — the default sort that floats Michelson rows above EVM rows as falsely "newest".

+

Cross-cutting, bundled in this passhygiene

Rename EtherlinkDepositOperation → L2DepositOperation, EtherlinkToken → L2Token, and the matcher locks — the names stop lying immediately and the migration churn lands once. Backfill = full reindex from the ground: all Tezos X data is test-net and re-syncable, so handlers repopulate every new column / FK / token-split correctly with no backfill script.

Why not a separate MichelsonDepositOperation table? The Michelson write surface is deposits only and will not grow (no FA on Michelson; withdrawals are EVM via NAC). A split pays a polymorphic-FK price across every consumer for a single stream. The discriminator closes the actual (matcher) bug, and l2_kind remains a clean cut-line if a split is ever justified later.
